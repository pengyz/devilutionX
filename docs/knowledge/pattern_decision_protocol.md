# 决策提问协议（经独立对抗复核修订）

**病灶不是"一问/多问"的频率**，而是三件事：**无分类判据、前提不绑定证据、许可型提问** ✗。

## 1) 判据（唯一入口）：按 **artifact 面** 分类，而不是按"我觉得玩家可见吗" ✗

**命中任一 ⇒ 必须问作者**：**存档格式** / **eval case** / **掉落与数值表** / **RNG 消费** / **可观测信息量**（玩家能看到的信息、操作负担）。
**理由**：主 agent 自己划"玩家可见"的线会**自证** ✗ —— 本项目的两次翻车都是这么发生的（"改一层怪物构成"被包装成"补一行数据"）。

## 2) 绝不问（自己定 + 记账本 ✓）
命名、文件布局、测试规模（N）、**由实测得出的具体数字**、可逆且不可见的实现路径。

## 3) 数字 vs 机制 ✗
实测只决定**数值**（可自定 ✓）；**是否引入一个玩家可感知的卡点/取舍**＝机制 ⇒ **必问** ✓。

## 4) 一次一问仅在"同一前提层"内成立 ✓
跨层依赖**拆开单问**（前提会互相污染 ✗）；同层、互不依赖的**批量 ≤5 条**，每条**必带默认值** ✓（本项目批量通过率 100% ✓）。

## 5) 五要素格式（缺一不可）
**前提**（标"已验证/未验证" ✓）→ **选项** → **各自后果（文件面 + 玩家面）** → **默认值** → **什么证据会推翻它**。

## 6) 先做后问 ✓
可逆、低风险、不阻塞的部分**先落地**；只留真阻塞点，并附"已按默认做完 X，仅 Y 待定" ✓。

## 7) 反"以批准之名改设计" ✗
问题必须**声明改动面**：是否改动**已批准文档的任一句** / **层构成** / **契约**；若是 ⇒ 标为**设计变更**并给出**旧文 diff**，**不得**包装成"补数据" ✓。

## 8) 不停等 + 待追认账本 ✓
作者未回 ⇒ 按默认推进并写入**待追认账本**（可回滚 ✓）；**仅不可逆项硬停** ✗。
每次交付附一行：**"本轮自主决定 N 项（可一键回滚）"** ✓。
**"按照建议来"不构成对未来同类问题的常设授权** ✗ —— 下次仍按 1) 分类 ✓。

## 9) 验证的度 ✓
只验证**会翻转推荐值**的前提，且**验证成本 < 默认值出错的重做成本**；否则带"**未验证**"标记照问 ✓。
9 次"未核验写文档"的病根是**缺少"每句挂证据"**，用"每句挂 `文件:行号` 或命令"来治 ✓（不靠"多验证" ✓）。

## 10) 三个新失败模式与缓解
| 失败模式 | 缓解 |
|---|---|
| 批量过长没人读完 | ≤5 条、每条一行、默认可一键接受 ✓ |
| **默认静默漂移**（作者不读 + 自主决定累积） | 待追认账本 + 每次交付一行"自主决定 N 项，可一键回滚" ✓ |
| 过度验证拖慢 | 时间盒 + 只验翻转推荐的前提 + 独立复核抽检"验证不足"（而不是要求全验）✓ |
