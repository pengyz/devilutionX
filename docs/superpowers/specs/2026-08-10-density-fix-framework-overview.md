## 1. 框架定位

修复 D1 怪物行为密度塌缩（扫描诊断：洞穴远程垄断 38%、地狱多样性骤降 + 数值悬崖、教堂无压力）。经 Oracle 框架评审 + 独立复核收敛为最小连贯包，按新优先序推进。

**框架不变量**（跨所有规格，违反任一条 = 规格不通过）：
1. **零新美术**：所有变体复用既有动画帧（special 帧）+ 既有 tint（TRN 换色）
2. **零新机制**：所有行为复用引擎既有原语（Rhino 冲锋 / Fallen 狂暴 / SpawnMonster / 光照 API）
3. **可读 tell**：每个新行为必须有游戏内可读的视觉提示（tint/姿态/低血），否则退化为背诵型未知（禁令 4 + B1 支柱）
4. **保留部分悬崖**：地狱数值悬崖是 D1 身份的一部分，可降不可清零（E1 硬约束）
5. **MP 确定性**：新 AI 按 per-tick aiSeed 重播种模型确定性推导（复用引擎 lockstep）
6. **timedemo/漂移硬门禁**：触碰层生成 RNG 或 monstdat 数值的规格须列 timedemo 重验成本

### 6.2 E1 REJECT 的核心教训（影响框架认知）

Oracle 用战斗数学证明「数值悬崖」诊断本身可疑：
- `hit = 2×(怪级−玩家级) + 30 − AC`，然后 `max(hit, GetMinHit())`——**地狱层 GetMinHit 15/20/25/30，任何 AC≥16 的角色都被钳在地板**，悬崖项完全无效
- 怪物 HP/伤害是固定列（`monster.cpp:208/:1218`），不受等级影响；玩家打怪命中公式（`player.cpp:548`）根本不出现怪级
- 等级只影响：掉落门槛、XP、被钳制的 2-4% 命中

> **⚠️ 2026-08-10 多 agent 复核证伪（见 §8.4）**：上述「GetMinHit 钳制」证明**公式漏 base toHit 项**（地狱 13-16 怪 toHit 列 90-130——Counselor 90 / Magistrate 100 / Balrog 130，monster.cpp:1274 `MonsterAttackEnemy(monster, monster.toHit(...), ...)`）。真实公式 `baseToHit + 2×(mlvl−plvl) + 30 − AC` 被 GetMinHit **下限**（抬高中招率）非消除等级项；Blood Knight 130+2×10+30−90 ≈ 100+ → 常驻命中，下限从不生效。「任何 AC≥16 被钳」证伪。**结论（不降数值）仍成立**，依据是「HP/伤害是固定列 + 等级项系数小（±2%/级）」而非此证明。

**合理路径**：E1 降级为「不降数值 + 记录悬崖轻微（3-6 级）且可接受 + 压力由行为规格承担」——实质并入行为规格。

### 8.4 多 agent 独立复核结果（2026-08-10 第二轮，4 个独立 Oracle 并行）

4 个独立 Oracle agent 并行复核全部规格 + 框架总览，每个**忠实重实现引擎逻辑**（不信任规格自述）。**发现先前所有评审（含 §8 的 9 项引擎事实验证）遗漏的系统性错误**：

| 规格 | 裁决 | 关键发现 |
|---|---|---|
| A1 教堂骷髅 | NEEDS-FIX | **冲锋伤害路径断裂**（special 列=0 → ~1 伤害）；狂乱者 no-op + 攻速/移速/无视硬直造假 + tell 不可见 |
| A3 洞穴风筝 | NEEDS-FIX | 同一伤害缺陷（Hell Stone Magma special 0-0 → 墙角惩罚=1 伤害）；「38% 垄断被打破」夸大 |
| B1 采样反垄断 | NEEDS-FIX | **27.8% L15 尾夸大 ~7×**（忠实模拟含 Golem 预算后真实 ~4.1%）；洞穴 cap 定义漏洞 |
| C2 熄灯者 | NEEDS-FIX | 死亡钩子读可变 `monster.enemy`（MP 清错玩家 + 可越界）；refcount 不对称；Infravision 反制对引擎为假 |
| A2 激励者 | NEEDS-FIX | 速度机制违反「零新机制」+ 代码引用错误（`rate` 是 AnimStruct 字段非 Monster::rate）；增益幅度未承诺 |
| **框架总览** | **NEEDS-WORK** | **§8.2 验证表自身含 2 处错误**（E1 GetMinHit 证明漏 base toHit；B1 27.8% 漏 Golem 预算） |

**关键错误细节**：

1. **冲锋伤害路径断裂（A1+A3 共享）**：`MissToMonst → MonsterAttackPlayer` 用 `minDamageSpecial/maxDamageSpecial`——8 骷髅 + Magma 系 special 列全 0 → 冲锋 ~1 伤害。§8.2#1 核实了「冲锋即时」但**从未核实伤害路径**——遗漏根源。
2. **B1 27.8% 是假数字**：忠实重实现 `GetLevelMTypes`（含 `AddMonsterType(MT_GOLEM)` 预加消耗 386 图片预算，monster.cpp:3441）后，L15 同类尾实际 **4.13%**（L14 0.70%、L13 0.00%）。27.8% 只在省略 Golem 预算时复现——v4 已按此重推导全部数值并诚实声明「小杠杆」。
3. **E1 GetMinHit 证明错误**：公式 `hit = 2×(mlvl−plvl) + 30 − AC` 漏 base toHit（地狱 13-16 怪 toHit 列 90-130——Counselor 90 / Magistrate 100 / Balrog 130，monster.cpp:1274 `MonsterAttackEnemy(monster, monster.toHit(...), ...)`）。真实公式被 GetMinHit **下限**（抬高中招率）非消除等级项。结论（别降级）靠「HP/伤害是固定列 + 等级项系数小（±2%/级）」仍成立，但 §8.2-9 的 ✅ 是错的（v5 已修正：GetMinHit 是下限非钳制，证明换血结论不变）。
4. **狂乱者三重造假（A1）**：`goal=Attack` 是纯 AI 攻击性非速度（FallenAi 2364-2368）；`SkeletonAi` 不读 goal → 伪代码 no-op；低血 tell 不可见（HP 条默认关）。

**核心结论**：框架是「reviewed to death」——文档跨评审自洽，但 5 次修订后仍带出错的数字。跨文档自洽 ≠ 正确，只有忠实引擎模拟能抓到。**建议先实现 B1 采样模拟 harness（纯测试，不改游戏代码）重新推导真实尾部数字**——最便宜地验证或否定旗舰声明。

### 8.5 关键共性问题（修复所有规格的前提）

**根因分层（§8.3 原始结论「虚构冲锋前摇」→ §8.4 独立复核深化）**：

1. **第一层（v3 已修）：虚构冲锋前摇**——A1/A3 都假设 `StartSpecialAttack` 能作为冲锋前摇（可打断），但引擎冲锋是即时的（同 tick 触发）。已修复：冲锋变体改为「即时冲锋」，反制改为「走位躲直线 + 冲锋冷却」，tell 用情境 + 冲锋启动时刻。
2. **第二层（v4/v5 已修）：冲锋伤害路径未核实**——两规格都设 `special 列 = 0` 后声称「冲锋伤害走普通伤害」，但引擎 `MissToMonst → MonsterAttackPlayer` 用 **special 伤害列** → 冲锋仅 ~1 伤害。已修复：给承载设 special 伤害列 = 普通伤害值（复用引擎既有路径）。
3. **第三层（v4/v5 已修）：行为声称未经引擎验证**——A1 狂乱者「攻速/移速/无视硬直」造假（goal=Attack 是纯 AI 攻击性）；A2 速度机制引用错误（rate 是 AnimStruct 静态字段）；C2 死亡钩子读可变 `monster.enemy`。已修复：狂乱者改 goal=Attack 纯攻击性、A2 移除速度机制、C2 记录固定目标。
4. **第四层（v4 已修）：数字未经忠实模拟**——B1 27.8% 漏 Golem 预算（真实 4.13%）；E1 GetMinHit 证明漏 base toHit（下限非钳制）。已修复：B1 重推导 + E1 证明换血。

**核心教训**：跨文档自洽 ≠ 正确——5 轮评审 + 整体验证都没抓到上述错误，只有多 agent **忠实重实现引擎逻辑**才暴露。规格引用引擎机制必须写「验证过的代码行 + 数字来源」。
