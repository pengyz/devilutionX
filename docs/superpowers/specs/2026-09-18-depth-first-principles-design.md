# 深度层规格：D1 体验的第一性重定（承重结构 · 存档契约 · 四个兑现）

**状态**：草案 v1（2026-09-18，待作者复核）
**分类**：**Depth**（限制信息、重塑压力、取舍；非数值膨胀；无开关 ⇒ 默认生效）
**上位文档**：宪章 `2026-07-27-better-d1-design-charter.md`（本规格为其 Depth 支柱的首次落地）；已实施的内容密度契约 `2026-09-16-content-density-contract-design.md`
**本规格的边界**：**只写设计面**（承重结构、存档契约、路线图与验收）。**不实现任何东西**；实现面条目按 §4.3 的路线图另行立项。

## 1. 问题陈述

**D1 的体验是一个自洽整体**（六件互相咬合，缺一即变质）：

| 结构 | 内容 |
|---|---|
| 两腔循环 | 城镇＝安全/经济/永久；地牢＝危险/发现/**单程** |
| 单位 | 一个角色的**一次下降**＝一局；**有限**（16 层）、**持久**、**不可逆** |
| 信息模型 | 地牢**未知但可学**；知识靠暴露挣得 |
| 资源模型 | 准备有限（腰带/卷轴/金币），**消耗发生在战斗内**，城镇是唯一补给点（回城卷轴＝泄压阀） |
| 威胁模型 | **低数量、高杀伤**；怪是"地点的一部分"，unique 是"事件" |
| 终局 | 最后一扇门**合上**弧线 ⇒ 游戏完结（没有跑步机） |

**业界缺少直接示例的原因**：**没有人深化 D1 的设计，大家换成了 D2 的设计**（无限、可重置、数值成长的跑步机）——D2 更成功，但它丢掉的是 D1 的承重结构。

**判定**：D1 的"薄"**主要是实现面**，外加**两处设计面缺口**。

| D1 的薄 | 归类 | 核验锚点 |
|---|---|---|
| 高难度＝**HP×3 纯倍率** | 实现面 | `Source/monster.cpp:255` ✓ |
| 怪物**无群体行为**（无编组/协同/威胁可读性） | 实现面（最大短板，我们已开工） | `Source/monster.cpp:3054 PlaceGroup`、`:318 GetUniqueMonstPosition` ✓ |
| 主题房存在但**无控制**（按频率随机放怪） | 实现面 | `Source/levels/themes.cpp:349 PlaceThemeMonsts`、`:913 CreateThemeRooms` ✓ |
| 物品模型薄（只有品质枚举，无独立词缀字段） | 实现面 | `Source/items.h:204 _iMagical` ✓ |
| 信息/UI 停在 1996 | 实现面（已在补） | `Source/levels/gendung.cpp:327 CanTarget` ✓（Dark Expedition 常开） |
| **① 存档模型破坏"不可逆"** | **设计面** | 见 §3/§4.1 |
| **② 信息/威胁只有单向**（怪不因光/声反应） | **设计面（待裁决）** | 见 §4.2 |

**本规格要解决的是设计面**：把"不可逆"从口号变成契约（§4.1），登记并裁决另一处缺口（§4.2），并把实现面的深化收敛成一条有验收的路线图（§4.3）。

## 4. 方案

### 4.1 第 0 章：存档契约（**三件套**，采纳作者的 (a)）

> **存档＝暂停 / 时间线唯一 / 死亡留痕**

| 条 | 内容 | 是否需新机制 |
|---|---|---|
| **存档＝暂停** | 离开时写档、回来继续 ✓；**不提供"回滚到死前"** ✗（无开关；契约唯一） | 否（改写档时机与语义） |
| **时间线唯一** | 单一连续时间线；**不新增多槽/自动备份** ✗ | 否 |
| **死亡留痕** | 死亡时执行**已实现**的 `StartPlayerKill(dropItems=true)`：装备掉在**死亡地点** ✓、掉一半金币 ✓、尸体留 `DeadPlayer` 标记 ✓、层持久 ⇒ **掉落还在原地** ✓（回收＝走回去捡） | **否**（机制已在，只改调用点的 `dropItems` 与存档时机） |

**为什么这不是"再加一条规则"**：它是 D1 **自己在多人模式里已经采用**的规则 ✓（同一份代码路径 ✓）——单机能读档是面向当年单机市场的让渡，不是设计核心。

**前置条件已具备**：作者已裁定**不保证存档格式兼容**（决策 34/35）⇒ 本契约只改**语义**，不改格式，无需迁移 ✓。

**风险（必须在验收里量化）**：①"不能撤销"会赶走存档刷/试错型玩家；②D1 的死亡后果只有"掉装备"（无经验/魂曲线）⇒ 惩罚强度需实测校准；③"死亡即写档"必须**不可被外部手段回滚**（否则契约形同虚设）。

### 4.2 缺口 ②：信息/威胁的双向性（**只登记，待裁决**）

现状：**你看不见它们**（Dark Expedition ✓），但它们**不因你的光/声而反应** ✗ ⇒ 信息只约束玩家、不约束怪物。补它＝**新增交互**（撞禁令 4 灰区）。**裁决判据（本规格建议）**：允许"既有概念之间的新交互"，但必须**玩家一局内能靠观察学会、且不需要记任何数字** ✓；否则不做。

### 4.3 四个兑现 + 一个合上（路线图：本规格只给方向与验收，实现另行立项）

| # | 兑现什么 | 承重结构 | 候选（锚点已核验） | 反制（红线 10） |
|---|---|---|---|---|
| ① | **情报可挣得** | 信息不对称 | 预告/侦查类（代价＝**决策权**，不是格子） | 可不用；代价可承受 |
| ② | **持久空间的取舍** | 不可逆 + 场所 | 守卫圣所（`themes.cpp:349` + `PlaceGroup`）：进不进这个房间 | 跳过 / 绕路 / 撤退 |
| ③ | **地点的赌注** | 场所实在性 | 成对神殿（每层"增益型 + 代价型"各一，一次性永久交换） | 不点、不买、不回城也能玩 |
| ④ | **威胁模型的实现** | 威胁模型 | 群体行为/威胁可读性（我们的小队机器已开工 ✓） | 引开 leader / 先杀 leader |
| ⑤ | **合上终局** | 终局 | 12→16 **有限**朝圣链（复用 boss 与事件；**禁止再加任何数值倍率** ✗） | 中途可退、进度持久 |

### 4.4 明确排除（都是"设计面加法"，会破坏整体）

新系统（装备/socket/技能树/meta 进度）✗；无限或循环终局 ✗；背包/战利品稀缺税 ✗；roguelike（每局重置 + 局外成长）✗。**理由统一**：它们改的是**设计**，而设计除 §4.1/§4.2 两处外是自洽的 ✓。

## 6. 验收标准（全部可失败）

| # | 判据 | 用例/证据 | 变红条件 |
|---|---|---|---|
| 1 | 死亡后**装备确实落在死亡地点附近** | 新 gtest：驱动 `StartPlayerKill(dropItems=true)`，断言 `InvBody` 清空且地面生成对应物品（复用 `DeadItem` 路径） | 掉落未发生 / 物品数量不符 |
| 2 | **死亡即写档** | 断言死亡路径触发 `pfile_update` 且档内角色已是死亡态（serial/mtime 变化） | 未写档 / 档内仍是死前状态 |
| 3 | **不存在回滚路径** | 断言：死亡写档后，正常流程**无法**把该档恢复到死前（无"读档到死前"的入口） | 出现任何可回到死前的正常入口 |
| 4 | **掉落持久** | 死亡 → 离开该层 → 重进 ⇒ 掉落物仍在（依赖 `diablo.cpp:3163` 持久分支） | 重进后掉落消失 / 层被重生成 |
| 5 | 惩罚强度校准（试玩协议） | 强制选择题 + 观测：死亡后 3 分钟内**主动再进同层**的比例、以及"惩罚过重"自陈 | 永久退出并报告"惩罚过重" > 40% ⇒ 撤销或改用 (b)/(c) |
| 6 | ④ 威胁形态的近/远程分别评估 | 沿用既有占比/施法者守卫 + 逐层评估表 | 任一职业出现无应对的层 |
| 7 | ⑤ 终局**不得新增倍率** | 断言朝圣链的实现不含 `maxHitPoints/maxDamage` 等倍率改动 | 出现任何新倍率 |

**反证条件（本规格的撤销判据）**：若验收 5 的数据显示"惩罚过重导致玩家放弃推进"，则本契约**撤销**，回到主 §4.3 的 ①②③④（即承认这处缺口不补，见 §7 附录的 (c) 分支）。
