## 1. 问题陈述

**失败点（Depth 规格 §1.2(4) 已核验）**：**战力↑ ⇒ 每次交战消耗↓**（需求端衰减 ✗）。

| 现状事实 | 锚点 | 后果 |
|---|---|---|
| 药水是**唯一"战斗内已消耗、不可预先规避"**的资源（P2 ✓） | `assets/txtdata/items/itemdat.tsv`（`IDI_HEAL`/`IDI_MANA`/`IDI_FULLHEAL` ✓） | 它是压力载体；但可被"多带"绕过 ✗ |
| 无自然回复 | `Source/player.cpp` 的 HP/MP 自增均为 Mana Shield/吸血类 ✓ | D1 吃消耗战（与 D2 相反） |
| 携带上限固定 | `InventoryGridCells = 40`、`MaxBeltItems = 8`（`Source/player.h:38-39` ✓） | 携带量是唯一约束 ⇒ 不足以形成压力 ✗ |
| 回城卷轴廉价 | 商店城内专属（`Source/stores.cpp:2471/2658/2776` ✓） | 压力被"**多跑一趟**"吸收 ✗（DP3 ✗） |

**目标（可操作）**：让**每个层段的下潜重新要求资源准备与中途抉择** ✓。
**判定分工（诚实）**：**机械侧**只判"形态是否按定义落地" ✓；"是否真的更紧张/不繁琐"**只能由预注册试玩判定** ✓（不得用击杀数/时间等自利指标 ✗，协议已禁）。

## 4. 方案

### 4.1 形态定义（层段 × {小队规模, 构成权重, 放置策略, 决策, 指名反制}）

> **参数为设计草案** ⚠（待人工审计后定稿）；**形态名与"决策/反制"是本规格的实质内容** ✓。

| 层段 | 形态名 | 小队规模 | 构成权重（name-level 草案 ⚠） | 放置策略 | **玩家决策**（红线 11） | **指名反制**（红线 10） |
|---|---|---|---|---|---|---|
| 教堂 **L1-8** | **可逃的围压** | 1–2 队/层 | 近战为主（教学） | 沿主通路、**可绕** | 打掉换经验 vs 绕开省资源 | 引开 leader（>4 格断链 ✓）/ 先杀 leader 拆队 ✓ |
| 洞穴 **L9-12** | **狭窄压制** | 2–3 队/层 | 远程/施法者落在**通路** | 卡在走廊/门口 | 掩体推进 vs 硬吃伤害 | 卡门位 / 贴身 / 拉出射程 ✓ |
| 地狱 **L13-16** | **消耗战** | 3–4 队/层 | 近战+远程**交替** | 分段、逼出**连续交战** | 手中药量 vs 推进深度：**何时回城** | 分段清场 / 回城卷轴认输离场 ✓ |
| Nest/Crypt **L17-24** | **精英抉择** | 2–3 队/层（含精英） | 精英 + 高威胁 leader | 与**通路/奖励**绑定 | 抢通路/战利品 vs 承担伤亡 | 绕路 / 时间差 / **放弃房间** ✓ |

### 4.2 放置实现（全部复用既有锚点 ✓）

1. **小队**：`PlaceGroup`（`Source/monster.cpp:3054` ✓）+ 拴系（`MonsterPack::Leashed` ✓）——**复用**已有 uniques 包逻辑 ✓；
2. **时机与位置**：在 `PlaceThemeMonsts`（`themes.cpp:349` ✓）的调用路径上，按**层段参数**决定小队数与构成权重 ✓；
3. **构成**：改 `level_rosters.tsv` / `level_roster_params.tsv`（生成构成 ✓）；
4. **硬约束（红线 9 ✓）**：**不改** `monstdat.tsv` 的任何数值字段 ✗、**不改** 掉落表 ✗、**不改** 商店/价格 ✗、**不新增物品** ✗。

### 4.3 与既有守卫的关系

| 守卫 | 关系 |
|---|---|
| `sampling_behavior_test`（密度/预算/确定性/leader） | **必须全量跑** ✓（形态改动直接触及其约束） |
| `level_roster_baseline_test`（占比/施法者/HF 组合数） | **必须全量跑** ✓ |
| **新增** `PressureShapeWithinBand`（每带一页断言：小队数/构成权重/放置策略在界内） | 新增 ✓，**可失败**（见 §6） |

### 4.4 "决策与反制"的可判定性（红线 10/11 的落地）

每个形态必须能用**一句"如果 X 则 Y"**描述，且 X/Y 都是**既有 UI 元素或既有概念** ✓：
- 例：地狱带——"**如果你在药量低于一半时继续推进，则下一次连续交战将迫使你使用回城卷轴**" ✓（X＝腰带药量 ✓，Y＝回城卷轴 ✓，都是既有元素 ✓）。

## 6. 验收标准

### 6.1 机械断言（进 `run_tests.py` / CI ✓；每条都可失败）

| # | 判据 | 变红条件 |
|---|---|---|
| 1 | **形态参数在界内**：每层段的小队数/构成权重落在参数表区间 | 改坏任一参数（如把地狱小队数调到 0 或超界）⇒ 红 ✓ |
| 2 | **逐层 × 职业构成表**（近战/远程/施法者计数与占比） | 改坏名册构成 ⇒ 红 ✓ |
| 3 | **既有守卫全量**（密度/占比/组合数/核心规模/唯一可达/HF 三项） | 任一退化 ⇒ 红 ✓ |
| 4 | **不变量**：`monstdat` 数值字段与掉落表**未被改动**（差异断言） | 改动任一数值/掉落 ⇒ 红 ✓ |
| 5 | **可绕性**（L1-8 教学带）：该层段小队**必须存在可绕路径**（放置策略断言） | 放置到不可绕位置 ⇒ 红 ✓ |

### 6.2 预注册试玩（判"体验"，**不进 CI** ✓）

| 项 | 内容 |
|---|---|
| 强制选择题 | "**哪一版更需要你在下潜前做准备 / 更需要你中途撤回？**"（A/B 盲测，按协议 ABBA ✓） |
| 反繁琐项 | "**哪一版更让你觉得在跑腿？**"（必须**不偏向新版本** ✓） |
| 结论规则 | 准备/撤回项须达协议阈值 ✓；**跑腿项若偏向新版本 ⇒ 撤销** ✓ |

### 6.3 前置基线（**必须先做**，否则"改坏了没有"无从判断 ⚠）

1. **机械可得**：各层段的**小队/构成/密度**基线（既有守卫输出 ✓）；
2. **只能由试玩取得**：各层段的**补给消耗 / 回城次数**基线（按协议预注册 ✓，不得事后调参 ✗）。

### 6.4 反证与撤销

① 深层**交战消耗未变**（形态无感）⇒ 撤销；② 玩家**完全靠逃跑/绕行摊平** ⇒ 形态只是障碍 ⇒ 撤销；③ 读作"**怪更多、更烦**"（数量≠压力）⇒ 撤销；④ **职业失衡**（近战或远程任一方出现无应对层）⇒ 撤销 ✓。
