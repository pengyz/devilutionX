## 1. 问题陈述

**症状**（可复现，扫描诊断 + 独立复核）：洞穴 9-12 层，池中 38% 是风筝怪；但因 `GetLevelMTypes` 随机采样，**单层可能随机抽出全是风筝怪**（图片预算限制下每层只有 2-4 种类型，随机性放大）。地狱 13-16 层，池中 6 类行为，单层随机抽 2-4 种可能全是同一行为类（如 2 只蛇 + 2 只召唤 = 全是近战）。

**效果诚实声明（v4 修正——据多 agent 独立复核 + 忠实模拟，见框架总览 §8.4）**：v3 声称「L15 同类尾 27.8%（评审忠实重实现采样循环实测）」——但该实现**遗漏了 Golem 预加预算**（`AddMonsterType(MT_GOLEM, PLACE_SPECIAL)` 在采样循环前执行，`monster.cpp:3441`，消耗 386 图片预算）。**本规格用忠实模拟（含 Golem 386）重新推导真实值**（方法见 §3.3）：
- **地狱 L15：4.13%**（v3 声称 27.8%——夸大 ~6.7×，仅在省略 Golem 预算时复现 27.83%）
- **地狱 L14：0.70%**（v3 声称 6.2%）
- **地狱 L13：0.00%**（v3 声称 2.2%）
- **洞穴 9-12 全风筝尾（风筝类 ≥3）：L9 0% / L10 2.4% / L11 0% / L12 2.6%**；**任意类 ≥3：L9 1.59% / L10 3.33% / L11 1.18% / L12 2.61%**（v5 修正——v4 的「0.6-2.7%」基于旧模拟且标签误写，引擎实测见 §3.3）
- cap 是**尾部保险**（消除 0.7-4.1% 的全同类层 + 洞穴 0-2.6% 的全风筝层），价值是「诚实的小杠杆」——v3 的「cap 价值反升」被推翻

**根因**（独立复核核实）：`GetLevelMTypes`（`Source/monster.cpp:3439`）的采样循环：

```cpp
while (nt > 0 && LevelMonsterTypeCount < MaxLvlMTypes && monstimgtot < 4000) {
    // 过滤图片超预算的类型
    // 随机抽 typelist[GenerateRnd(nt)]
}
```

- **无行为构成约束**——随机抽到什么都行，可以全是风筝、全是近战
- **MaxLvlMTypes=24 实际不约束**（地狱图片 980-2220，4000 预算下每层只放得下 2-4 种）
- **逐层体验**：洞穴单层 2-4 种，随机性导致「全风筝层」概率真实存在

## 4. 方案

### 4.1 采样约束：逐层行为构成上限

**核心改动**：在 `GetLevelMTypes` 采样循环内，追踪已采样类型的**行为类**，同一行为类超过上限时跳过（不加入 typelist 候选）。

| 层段 | 约束 | 依据 |
|---|---|---|
| 洞穴 9-12 | 风筝类 ≤ 2 种/层 | 打破「全风筝层」——池 38% 但单层最多 2 只风筝 |
| 地狱 13-16 | 同类 ≤ 2 种/层 | 打破「全近战层/全远程层」——保证单层行为混合 |
| 教堂 1-4 | 无约束（池已均衡） | 教堂无压力问题靠 A1，非 B1 |
| 墓穴 5-8 | 无约束（多样性峰值） | 最小问题 |

**对玩家的影响**：逐层战斗从「随机可能全风筝/全近战」变为「每层行为混合」——玩家面对的战斗更接近扫描文档的「池多样性」而非「采样偶然性」。

**为什么不提高图片预算**：独立复核指出提高 4000 预算可增加每层类型数，但涉及平台内存（Vita/3DS/Amiga）——本规格不触碰预算，只做行为构成约束（零风险）。

**地狱每层 2-4 种的限制是否保留**：保留——这是图片预算决定的身份约束（D1 地狱本来每层怪物少而精）。B1 不改变类型数量，只保证已采样的 2-4 种行为不同。

**v3 映射修正（据整体验证 §8.2-4）**：v2 误把 Counselor 归入「鼓舞组织」。代码核实：`CounselorAi`（monster.cpp:2724）用 `StartRangedAttack` 施放 Firebolt/ChargedBolt/LightningControl/Fireball（2750-2755）——**远程站桩**，非鼓舞（鼓舞是 Fallen 的 `goal=Attack` 同族激励）。此映射修正本身正确。**注意（v4）**：v3 据此推出的「同类尾升至 27.8%」数值错误——忠实模拟（含 Golem 预算）后 L15 真实 4.13%（见 §3.3）。
