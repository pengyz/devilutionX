# 地狱悬崖评估（Hell Cliff Assessment）设计

**日期**：2026-08-10（v1「地狱重组」被 Oracle 首轮评审 REJECT；v5 据多 agent 独立复核修正 GetMinHit 证明）
**状态**：草案（v5——独立复核证伪 GetMinHit 证明，结论保留；评估文档，无代码改动）
**分类**：Expansion（宪章决策 31 定位变更后；评估文档，不实施数值改动）
**取代**：`2026-08-10-hell-recombination-design.md`（v1「地狱重组」，被 Oracle REJECT——按宪章决策 9 先例不归档，内容错误留着会被当参考；裁决记录见框架总览 §6.4）

> **定位**：对扫描诊断的地狱 13-16「数值悬崖」做**评估并裁决**——不实施数值改动（Oracle 证明降级是错误杠杆），把地狱压力修复**交由行为规格承担**（A1/克隆族区分）。

> **v5 相对 v1-重构版的变更**（据多 agent 独立复核，见框架总览 §8.4——GetMinHit 证明证伪）：
> - **GetMinHit 证明修正**：v1/重构版声称「`hit = 2×(怪级−玩家级) + 30 − AC`，任何 AC≥16 都被钳在地板，悬崖项完全无效」——**公式漏了 base toHit 项**（地狱怪 `toHit` 列 90-130：Counselor 90 / Magistrate 100 / Balrog 130，monster.cpp:1274 `MonsterAttackEnemy(monster, monster.toHit(...), ...)`）。真实公式 = `baseToHit + 2×(mlvl−plvl) + 30 − AC`，`max(hit, GetMinHit())` 是**下限抬升**（保证最低 15-30 中招率），**非消除等级项**——Blood Knight（toHit 130）130+2×10+30−AC 在 AC 60-120 玩家下 ≈ 100+，**下限从不生效**，「任何 AC≥16 被钳」**证伪**
> - **等级项真实影响**：等级差项系数仅 2（每级 ±2% 中招率）——**影响微小但存在**（非 v1 声称的「完全无效」）；GetMinHit 只在极端低 base toHit + 高 AC 时才抬升
> - **结论保留**：**不降数值**仍成立——依据从「GetMinHit 钳制」改为「**HP/伤害是固定列**（monster.cpp:208/:1218，不受等级影响）+ 等级项系数小（±2%/级，降 1-2 级只挪 2-4% 中招率，不减轻实际压力）」——证明换血，结论不变

> **v1 REJECT 的核心教训（Oracle 首轮评审，7 个 blocking 中最重）**：
> - **「数值悬崖」诊断错误**：战斗数学证明怪物等级对战斗压力几乎无贡献——`hit = baseToHit + 2×(怪级−玩家级) + 30 − AC`（v5 修正：v1 漏 base toHit，地狱怪 90-130），等级项系数仅 2（±2%/级）
> - 怪物 HP/伤害是固定列（`monster.cpp:208/:1218`），不受等级影响；玩家打怪命中公式（`player.cpp:548`）根本不出现怪级
> - 降级既非新内容也非机制修改（红线 9 回避）；且玩家模型未验证、掉落收缩、行为无地狱投递载体
> - **结论**：地狱的「难」来自 HP/伤害固定列 + 行为多样性（6 类→换皮），不是等级。修复方向是**行为**（克隆族区分），不是数值。

## 1. 问题陈述

**症状**（可复现，扫描诊断）：地狱 13-16 层多样性骤降——23 种池只分 6 类行为，每类 3-4 种全是同族换皮（蛇 4、骑士 4、召唤 4、传送 4、远程拉扯 4、巨型 3）。

**v1 曾认为的「数值悬崖」（已被 Oracle 证伪 + v5 修正证明）**：
- 扫描假设：怪级 21-30 vs 玩家 13-19（差 8-11 级）→ 数值碾压
- 独立复核修正：玩家实际约 18-24 级（XP 曲线），悬崖仅 3-6 级
- **Oracle 战斗数学（v5 修正）**：真实命中公式 `hit = baseToHit + 2×(怪级−玩家级) + 30 − AC`（地狱怪 baseToHit 90-130，monster.cpp:1274），等级项系数仅 2——**等级对中招率的贡献微小（每级 ±2%）但非零**（v1 声称「完全无效」证伪）；`GetMinHit` 是**下限抬升**（保证最低中招率），非钳制上限——高 baseToHit 怪（Blood Knight 130）下从不生效

**真实的地狱问题**（Oracle 判定）：
1. **行为多样性骤降**（真问题）：6 类行为全是换皮——这是 A1/克隆族区分的修复目标
2. **HP/伤害数值**（固定列，非等级）：地狱怪 HP 100-225、dam 20-35——这是 D1 身份的一部分（「保留部分悬崖」框架不变量），不是要修的 bug

## 4. 方案（评估裁决，无实施）

### 4.1 裁决：不降数值，悬崖保留

**决策**：地狱怪物等级**不做任何修改**。理由（Oracle 首轮评审 + v5 证明修正）：
1. 降级是错误杠杆——等级项系数仅 2（±2%/级），降 1-2 级只挪 2-4% 中招率 + 掉落门槛 + XP，不减轻任何实际压力（v5 修正：依据从「GetMinHit 钳制」改为「等级项系数小 + HP/伤害是固定列」——证明换血，结论不变）
2. 降级会收缩掉落（25-27 unique 门槛从普通怪消失）——在错误杠杆上引入掉落风险
3. 悬崖（3-6 级）本身轻微且是 D1 身份一部分（框架不变量「保留部分悬崖」）

### 4.2 地狱压力修复的正确路径：行为规格

地狱的「难」来自：行为多样性骤降（6 类换皮）+ HP/伤害固定列。修复：
- **行为多样性**：由克隆族区分规格承担（地狱蛇/骑士/召唤/传送系的换皮区分）——**本规格的实质交付是记录此依赖**
- **HP/伤害**：不修改（D1 身份，框架不变量）

### 4.3 交付物

本规格不产生代码改动，产生：
1. **悬崖评估记录**（本文档）——证明「数值悬崖」非真实问题，防止未来错误立项
2. **行为规格依赖声明**——地狱多样性修复必须由克隆族区分规格承担（该规格需覆盖地狱蛇/骑士/召唤/传送系）
3. **知识沉淀**——「怪物等级对战斗压力贡献微小（等级项系数 2，±2%/级；HP/伤害是固定列）」写入知识库 gotcha（v5 修正：原文「GetMinHit 钳制」证伪——GetMinHit 是下限非钳制）
