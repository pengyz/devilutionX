# 法术系统

> D1 的法术系统通过属性上限实现了隐式职业边界。法术的真正问题不是"能不能学"，而是"学了有没有用"。

## 职业边界：属性上限（事实）

| 职业 | 魔法上限 | 能投资的魔法点 | 能学的最高法术 |
|------|---------|--------------|--------------|
| 战士 | 50 | 40 | ManaShield (45) 勉强 |
| 游侠 | 70 | 55 | Elemental (70) 勉强 |
| 法师 | 250 | 215 | 全部 |

**设计价值**：这是 D1 最精妙的设计之一。不需要额外的法术等级系统，属性上限自然限制了职业边界。战士能学低级法术（需要投资），但学不了高级法术。

## 法术实用性分析（事实 + 问题）

### 有用的法术（有明确使用场景）

| 法术 | 使用场景 | 职业价值 |
|------|---------|---------|
| **Firebolt** | 基础远程攻击 | 所有职业 |
| **Healing** | 生存必需 | 所有职业 |
| **Town Portal** | 安全返回 | 所有职业 |
| **Identify** | 信息获取 | 所有职业 |
| **HolyBolt** | 对亡灵额外伤害 | 所有职业 |
| **Lightning** | 中程 AOE | 法师、游侠 |
| **Flash** | 近程 AOE | 法师、战士 |
| **Fireball** | 远程 AOE | 法师 |
| **Chain Lightning** | 远程链式 AOE | 法师 |
| **Teleport** | 机动性 | 法师 |
| **Mana Shield** | 生存手段 | 法师 |
| **Stone Curse** | 控制手段 | 法师、游侠 |

### 问题法术（使用场景模糊）

| 法术 | 问题 | 改进方向 |
|------|------|---------|
| **Rage** | +攻击 -防御 +受伤——风险太高，收益不够 | 增加收益（如+暴击率），让风险/回报更合理 |
| **Etherealize** | 穿墙穿敌——场景太窄 | 增加用途（如穿墙时无敌、穿敌时造成伤害） |
| **Invisibility** | 代码中未实现 | 实现或删除 |
| **DoomSerpents** | 效果不明 | 需要明确效果描述 |
| **BloodRitual** | 效果不明 | 需要明确效果描述 |
| **Golem** | 召唤物太弱 | 增加 Golem 的实用性 |

### 设计原则

1. **每个法术都有明确的使用场景**——如果玩家不知道什么时候用这个法术，法术设计失败了
2. **法术之间的差异是质的，不是量的**——Fireball 不只是"更强的 Firebolt"，它是 AOE
3. **法术的价值由场景决定**——Stone Curse 在 Boss 战中无价，在清怪中无用，这是好的设计
