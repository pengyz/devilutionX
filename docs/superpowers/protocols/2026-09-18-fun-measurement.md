# 试玩判定协议（预注册）——变体间偏好测量

**状态**：预注册 v1（2026-09-18）。**本文件必须在试玩开始前冻结**；开跑后不得修改判定规则。
**适用**：任何**玩家可感的内容/机制改动**（Expansion 类）。目的不是给"好玩"打程序化分数，而是在**事先写死的规则**下得出一个**可判定、可回退**的结论。

## 0. 措辞规则（硬约束）

- 结论单位**只能**是"**变体 X 相对变体 Y 的偏好**"，并附**噪声下限**与**样本量**。
- **禁止**写"游戏更好玩了""玩家更喜欢"这类总体断言；**禁止**用本协议的结果推广到未参与试玩的人群。
- 每条结论必须同时写出：**支持它的证据**、**能证伪它的观察**、**样本能测出的最小效应**。

## 1. 候选结论与回退触发（预注册）

| 观测（按第 3 节流程得到） | 判定 | 动作 |
|---|---|---|
| 方向一致题 ≥16/21 且第 7 题指向同一变体 | **偏好该变体** | 保留；写台账 |
| ≤5/21 或方向与第 7 题相反 | **偏好相反变体** | **回退触发：撤销该改动**（或改成对照变体） |
| 方向不一致（题间分裂） | **分裂** | 以第 7 题裁决，**记录分裂清单**；禁止取平均 |
| 全部落在噪声带内（见 §3 A/A 基线） | **无差异** | 若**测前未登记**该改动的"非 fun 理由"（缺陷修复/密度地板等）⇒ 判"**不值得继续投入**"并按回退触发处理；若已登记 ⇒ 仅以该理由保留，并注明"玩家未察觉" |

## 2. 题库（7 题，全部**强制二选一**，不用量表）

1. 哪一次你更想继续打下去？
2. 哪一次你更能说出这一层的"招牌怪"？
3. 哪一次更常出现"没想到会遇到这个"？
4. 哪一次更觉得"这些怪在配合"？（小队）
5. **哪一次更单调？**（反向题，用于检出赞成/期待倾向）
6. 哪一次更有压力？
7. **若只能保留一个版本，你留哪个？**（整体偏好，裁决题）

## 3. 设计（先证仪器、再测差异）

1. **A/A 空对照（必跑，先跑）**：同一构建、同一层序、同一时长跑两次。若出现"偏好某个变体"⇒ **仪器在造噪声**，本次结论作废（这是仪器的**可失败证明**）。
2. **A/B/A 含重复**：A 与 B 各出现两次；由两次 A 的答案算出**答案自一致性**，得到 **N=1 的噪声下限**。
3. **会话内交替 ABBA**，摊平学习曲线；**玩家间顺序平衡**（一半玩家 A 先）。
4. **首层作"冷读"**（玩家对两版都陌生），不计入判决题。
5. 固定条件：同一角色、同一层序（例如 L1→L8）、同一时长（20 分钟/轮）、**同一种子序列**。

## 4. 对照变体的构造（同种子、只差一个变量）

| 实验 | A（出厂） | B（对照） | 构造方式 |
|---|---|---|---|
| **小队** | `squad_chance=30` | `squad_chance=0` | 用 `test/fixtures/txtdata/monsters/level_roster_params_squads_off.tsv` 覆盖 `assets/txtdata/monsters/level_roster_params.tsv` → `ninja -C build devilutionx_mpq`；`git checkout --` 还原 |

两个变体**必须**用同一提交构建，只有该表不同（构建后在报告中记录 `git rev-parse HEAD` 与表的 hash）。

## 5. L2 行为代理（准入规则，默认**不采**）

- **准入条件（必须全部满足）**：①能说出**至少两个竞争解释**；②这两个解释对"好"的**预测符号相反**；③度量方式能区分它们。
- **排除自利指标**：击杀数、XP、时长、伤害量——加怪/加内容必然使它们上升，会**系统性给密度类改动背书**，一律不作为"更好"的证据。
- 当前唯一准入代理：**"死亡后 N 分钟（N=3）内主动再进同一层"**（区分"投入"与"卡住/刷装备"：后者通常表现为换层或长时间停留）。
- 采集前提（若将来要做）：**默认关**、显式 `--playlog <path>`、**不写存档**、每层 flush、路径不可写/磁盘满 ⇒ **静默禁用并有警告**，绝不影响游戏；需有对应 gtest 断言（这是 Infra 类，I1-I4 逐条填）。

## 6. L3 观察（复用规格附录 D 的 5 条预测，不另立清单）

预测 1（同层连进三次见到同一批 core）、预测 2（地狱单局可见种类）、预测 4（随从未被强化）→ 各自二值化为"能/不能说清"。
预测 5（引开 leader >4 格脱队、靠近归队）→ **必须人工执行**：找小队 → 引开 >4 格观察脱队 → 靠近观察归队。

## 7. 小样本诚实性（必须写进结论）

- **N=1**：只能作**预注册个案**，只能测出**大效应**；不得表述为人群结论。
- **N=3**：仍属**探索性**；结论里必须写"能测出的最小效应"与"本样本无法排除的替代解释"。
- 汇总口径：每玩家 7 题 → 每人最多 21 次强制选择（A/B/A×7）→ 符号检验阈值**写死为 ≥16/21**。

## 8. 结果去向（不进 eval、不进全量门禁）

人工判定**不可复现**，因此：**不写成 eval case**（`tools/eval/models.py:155` 明确 gtest-only），**不进全量门禁**。结果落 **SDD 台账** + `docs/knowledge/`（`decision` 类，含"正反馈也写"）。

## 9. 边界

AI 负责：造对照变体、冻结协议、执行流程、按 §1 规则计算、记账、写判据。
AI **不得**：代替玩家给出偏好、用"我认为玩家会喜欢"当证据、在噪声带内宣称得到差异。

## 10. 首个实验执行清单（小队 on/off）

1. 冻结本文件（记录其 hash）；
2. `git rev-parse HEAD` 记录提交；构建 A（出厂）；
3. 覆盖参数表为 `squads_off` → `ninja -C build devilutionx_mpq` → 构建 B，记录表的 hash；
4. **先跑 A/A 空对照**（20 分钟×2）→ 检查是否出现假偏好；
5. 再跑 A/B/A（每人 3 轮，ABBA 顺序，首层冷读）；
6. 填会话卡（见下）→ 按 §1 计算 → 写台账与知识条目；
7. `git checkout -- assets/txtdata/monsters/level_roster_params.tsv` 还原，确认工作区干净。
